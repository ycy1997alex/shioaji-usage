目的：不必啟動程式即可核對 UI 版面與互動行為是否做對。版面示意為 HTML mock，非截圖。左側導覽可跳章，各對應表可展開／收合。

0. 概觀與程式結構

本工具採 MVP 分層：View（views/，純 UI，不 import shioaji）、Model（models/，資料與外部服務，不 import tkinter）、Presenter（presenters/，唯一跨層橋樑）。UI 相關只有兩個視窗類別：

UI 元素類別檔案
主視窗儀表板MainView(tb.Window)views/main_view.py
金鑰設定對話框LoginDialog(tk.Toplevel)views/login_dialog.py

兩個 View 都不含業務邏輯：MainView 只暴露 on_query/on_settings/on_close callback 與 render_usage/render_status/set_busy/show_error 更新方法；LoginDialog 只把輸入放進 self.result。實際流程由 UsagePresenter（presenters/usage_presenter.py）驅動。

4. 互動流程（使用者動作 → handler → model 呼叫 → UI 更新）

4.1 啟動

main() → presenter.start() → usage_store.load_last_usage() ├─ 有紀錄 → view.render_usage(record)：顯示上次數值與時間 └─ 無紀錄 → view.render_usage(None)：儀表全「—」、「尚無查詢紀錄」 → view.render_status(False)：● 未連線 ※ 啟動一律不連線、不登入（D2）

4.2 查詢

點「查詢」→ _handle_query → on_query → presenter.query() ├─ client.is_logged_in ─→ set_busy(True) → 背景 _fetch_usage_job → client.get_usage() └─ 未登入 → config_store.load_keys() ├─ 有金鑰 → 直接用存檔金鑰＋上次模式 └─ 無金鑰 → _ask_credentials → LoginDialog（取消＝return，不 busy） → set_busy(True) → 背景 _login_and_fetch_job → client.login(fetch_contract=False) 成功 → view.after → _save_credentials（save_keys 加密＋save_config 記模式） → _fetch_usage_job → client.get_usage() 失敗 → view.after → _on_login_failed → set_busy(False)+render_status(False) → show_error(中文說明＋login_retry_guidance) → open_settings() usage 成功 → view.after → _on_usage_ok → usage_store.save_last_usage(record)（覆寫＝舊資料即刪除） → render_usage(record) + render_status(True)（保持登入 D4）+ set_busy(False) usage 失敗 → view.after → _on_usage_failed：set_busy(False)+show_error；畫面保留舊紀錄

login／usage 為網路呼叫，一律走 _run_in_thread 背景執行緒，再以 view.after(0, ...) 回主執行緒更新 UI（tkinter 只能在主執行緒動 UI）。

4.3 金鑰設定

點「金鑰設定」→ on_settings → presenter.open_settings() → load_keys() 預填 → _ask_credentials → LoginDialog 確認 → _save_credentials（立即加密儲存新金鑰＋新模式） → 若 client.is_logged_in → client.logout() + render_status(False) （下次查詢用新設定重新登入，D4） 取消 → 無任何變更

4.4 關閉

視窗 ✕ → _handle_close → on_close → presenter.close() → 若 is_logged_in → client.logout()（釋放連線）→ view.destroy()

5. 狀態管理（狀態放哪、如何傳遞）

沒有全域狀態容器；狀態分散在三處，一律經 Presenter 讀寫、單向推給 View 呈現。

狀態存放位置持久性誰改它 / 如何傳遞
登入狀態、帳戶模式（是否模擬）、Shioaji 連線物件ShioajiClient._logged_in / _simulation / _api（記憶體）執行期；有 threading.Lock 保護（背景執行緒會動）login/logout 改；presenter 讀 is_logged_in/simulation → render_status
上次選擇的帳戶模式UsagePresenter.cfg ←→ .data/config.json落地（明文 JSON）load_config 啟動載入；查詢/設定成功 save_config 寫回
API 金鑰.data/secrets.bin（加密）落地（DPAPI／Fernet）save_keys/load_keys；不進 View、不留記憶體單例，用完即傳參
上次查詢數值.data/last_usage.json落地（單筆整檔覆寫）save_last_usage 寫、load_last_usage 讀 → render_usage
UI 呈現狀態（儀表數值、按鈕忙碌）View 各 widget不持久，View 內只由 presenter 呼叫 render_usage/render_status/set_busy 設定，View 不自行決策

傳遞方向恆為單向：Model（檔案/記憶體）→ Presenter 組 record → View.render_*。View 從不反向讀 Model，也不保存業務狀態；使用者輸入只經 callback 交回 Presenter。

6. 驗收檢核表

#檢核項
1視窗出現在螢幕 10%,10%、佔寬高各 50%；無法縮得比預設更小
2標題列與工作列圖示皆為專屬 icon；標題含 by Alex Yu 與 v 日期
3首次啟動顯示「尚無查詢紀錄」；查詢成功後重開程式，直接顯示上次數值（狀態＝未連線）
4查詢中按鈕變「查詢中…」且兩顆皆不可連點；完成後恢復
5用量 ≥80% 儀表變紅（danger）
6第二次按查詢不重新登入（明顯較快，走 _fetch_usage_job）
7錯誤金鑰 → 中文錯誤說明 + 自動開金鑰對話框，程式不崩潰
8金鑰只存在加密檔 secrets.bin；config.json 內無明文金鑰
9改金鑰/模式後若原本已登入 → 自動登出，下次查詢用新設定
